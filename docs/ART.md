# Art pipeline: palette, textures, skies and sprites

Owner: **art**. Everything you see in the 3D views (walls, floors, skies,
demons, pickups, props, effects) is **procedurally generated by C code at
build time** and shipped as `const` tables, so on the GBA it all lives in
ROM and costs no RAM.

```
core/art/*.c ──(host gcc)──> core/tools/artgen ──> core/gen/art_data.c (committed)
                                    │
                                    └── --sheet DIR ──> PNG contact sheets for review
core/src/palette.c   the 256 colours (hand-picked), names, palette helpers
core/src/textures.c  texture_pixels / texture_image / sky_pixels (lookups only)
core/src/sprites.c   sprite_image / sprite_frames / sprite_flags (lookups only)
```

## Commands

| Command | What it does |
|---|---|
| `make -C core gen` | rebuilds `artgen` and rewrites `core/gen/art_data.c` (plus the other generators) |
| `make -C core check-gen` | regenerates into a temp dir and fails if anything differs (CI) |
| `$BUILD/artgen --out-root DIR` | writes `DIR/core/gen/art_data.c` |
| `$BUILD/artgen --sheet DIR [--zoom N]` | writes contact sheets (see below) |
| `$BUILD/artgen --check --stats` | runs every generator + validation, prints byte sizes per sprite and seam diagnostics |

`artgen` is built from `core/tools/artgen*.c`, `core/art/*.c` and
`core/src/palette.c` (+ fixmath/rng, unused). It is integer-only and
seeded: no floats, no libm, no time, no `rand()`, so `art_data.c` is
byte-identical on every machine. It validates as it goes and exits non-zero
on errors, so `make gen` / `check-gen` catch broken art: every `TEX_*`,
`SKY_*` and `SPR_*` id must be defined exactly once, frame counts must fit
the header limits, no texture or sky may contain index 0, the colormap
must be identity at level 15, black at level 0, never touch index 0 and
never get brighter at a lower level, every demon must have 8 frames,
every sprite frame must be non-empty and centred (even width), ground
sprites must stand on their bottom row in frame 0, and demon corpses
(frame 7) must lie on the ground.

Contact sheets written by `--sheet`:

| File | Shows |
|---|---|
| `palette.png` | the 256 entries, 16 per row |
| `colormap.png` | every index at the 16 light levels (left: 1-127, right: 128-255) |
| `tints.png` | the six tint maps |
| `textures.png` | every texture frame, zoomed |
| `tiles_a.png`, `tiles_b.png` | each texture tiled 3x3 at 1x (seam check) next to light levels 15/11/7/3 |
| `skies.png` | each sky plus half a wrap (horizontal seam check) |
| `sprites_demons.png`, `sprites_fx.png`, `sprites_items.png` | every frame of every sprite on alternating pastel / dark rows |

Always look at the sheets after changing a generator.

## Art direction (how the generators implement it)

Premium, cute, lively, vaguely furry (see ARCHITECTURE.md "Art direction"):

* **Soft 3-4 tone shading, hue-shifted.** Sprite primitives are lit with a
  squared half-Lambert term from the top-left and picked into a material of
  4-5 colours taken from the hue-shifted ramps (shadows lean cool/purple,
  highlights warm). A cool **rim light** brightens the shadow-side edge.
* **Coloured selective outlines.** `spr_outline()` puts a 1px outline
  around the silhouette in a dark shade *of the neighbouring colour*
  (`art_outline_of`), one step lighter on the lit top-left, one step darker
  under the feet. Pure black never appears in an outline unless the colour
  itself is black.
* **Inner contours.** `spr_contours()` darkens a part by two steps (inside
  its own colour family) where a part drawn later overlaps it, which reads
  as both an inner line and soft ambient occlusion.
* **Fluff.** `spr_fluffy()` breaks an ellipse rim into pointed fur tufts
  (cheeks, chest fluff, tail tips, plush stuffing, foliage).
* **Glossy eyes.** `part_eye_cute()` (iris gradient, dark upper lid, two
  highlights) and `part_eye_glow()` (glowing slit demon eyes).
* **No noise.** Dithering is only used as a soft 50% checker at band edges
  (vapour, clouds); dissolving frames erode in 2x2 clumps, and
  `spr_clean()` removes orphan pixels.
* **Contrast.** The cute set is pastel candy-land; the hell set is
  grotesque Doom (flesh, bone, blood, lava, rust, vape clouds).

## The palette (`core/src/palette.c`, layout in `palette.h`)

| Indices | Contents |
|---|---|
| 0 | transparent (black when used for a rect/clear) |
| 1-15 | UI colours (`PAL_*`): black, white, greys, pink, mint, cream, reds, gold, vape purple, tamagotchi LCD green |
| 16-111 | 32 paint colours x 3 shades (dark, base, light) - creator colours |
| 112-135 | 8 natural skin tones x 3 shades |
| 136-255 | 15 environment ramps x 8 shades, dark to light |

Ramps: STONE (cool lavender grey), WOOD (red-brown, doubles as rust),
GRASS (teal to butter), PASTEL_PINK (raspberry to strawberry milk), SKY
(midnight to noon, also water and night), VAPE (violet vapour), CANDY
(butterscotch to lemon cream: sand, gold, stars), MINT, PEACH (cocoa to
peach cream: paths, cute walls), BLOOD, LAVA (ember to white-hot), FLESH
(bruise to raw pink), BONE, SICK (bile green), STEEL (gunmetal).

### Shade families, colormap and tints (`core/art/art_palette.c`)

Every index belongs to a **family** (its ramp, its paint's 3 shades, its
skin tone, or a small UI group). Each paint / skin / UI colour also has a
**related ramp** (e.g. BUBBLEGUM -> PASTEL_PINK, LAVENDER -> VAPE,
CHOCOLATE -> WOOD) that it continues into when its own shades run out.

* `doomo_colormap[16][256]` (light levels): level 15 is the identity,
  level 0 is black, index 0 always stays 0. For each colour and level the
  target brightness is `luma * f(level)`; the colour **walks down its own
  family / related ramp** to the member whose brightness matches (so a
  pastel wall in shadow becomes a deeper, richer pink, not grey). Only
  below the family's darkest shade does it fall back to the perceptually
  nearest ("redmean") colour, with hue preservation and a slight cool tint.
  The table is forced monotonic (never brighter at a lower level).
* `doomo_tintmap[TINT_*][256]`: damage red, holy gold, sick green, vape
  purple haze, and NIGHT (desaturated moonlit blue; emissive colours such
  as lava, gold, LCD green and white stay lit, so windows and lava glow at
  night).
* `palette_darker()` / `palette_lighter()`: one shade step inside the
  family (paints continue into their related ramp) - used for outlines,
  hover states, highlights.

The tables are computed by artgen and stored const in `art_data.c`;
`palette_init()` copies colormap + tintmap into RAM (5.5 KB).

## Sprites

Every image is **centred on its x axis** (even width; the anchor column is
the middle). Index 0 is transparent and boxes are tight.

* **Ground sprites** (demons, pickups, props): the bottom row is the
  feet / floor contact. Draw with the billboard `z` = floor height.
* **`SPRF_CENTERED`** (projectiles, effects): the box is symmetric about the
  object's centre in x and y, so draw it with feet `z = centre_z - h/2`.
* `sprite_flags()` hints: `SPRF_FULLBRIGHT` (draw with `BB_FULLBRIGHT`),
  `SPRF_FLOATS` (flyer: altitude comes from the actor's z, the art has no
  hover gap), `SPRF_TRANSLUCENT` (ghostly, use `BB_TRANSLUCENT` if
  supported), `SPRF_LOOP` (idle loop), `SPRF_ONESHOT` (play once).

## Runtime API (core/src/textures.c, sprites.c, palette.c)

* `palette_init()`, `textures_init()`, `sprites_init()` - call once at
  boot (the lookups also self-initialise lazily).
* `texture_pixels(id, time)` returns the frame for `time` (ticks) per the
  texture's animation mode (`DOOMO_ANIM_LOOP`, `PINGPONG`, `FLASH`);
  invalid ids fall back to TEX_GRASS (the same as `map_cell_safe`'s wall 1).
* `texture_image(id, time)` / `sprite_image(id, frame)` return stable
  `DoomoImage`s: one per frame, uid assigned once from
  `doomo_image_new_uid()` at init, so the PS1 can cache uploads by uid.
  Sprite frames are clamped; invalid sprite ids return an empty 2x2 image.
* `texture_avg(id)` (minimap / far LOD colour), `texture_frames`,
  `texture_is_animated`, `texture_name`; `sky_pixels`, `sky_horizon`
  (horizon colour for fog), `sky_is_animated`; `sprite_frames`,
  `sprite_flags`, `sprite_name`.

RAM: colormap + tintmap 5.5 KB, image wrappers ~3.4 KB; everything else is
const.

## Adding or changing art

1. Write or edit the generator function in the matching `core/art/*.c`
   file and register it in that file's table (`art_tex_*`, `art_skies`,
   `art_spr_*`) with its id, name, frames, speed/anchor and mode/flags.
2. New ids go into `textures.h` / `sprites.h` before `*_COUNT` (never
   reorder: ids are used in maps and saves).
3. `make -C core gen`, then `artgen --sheet DIR` and **look** at the
   sheets: silhouettes, outlines, tiling, light levels, sizes.
4. Commit the generator and the regenerated `core/gen/art_data.c`
   together (CI runs `check-gen`).
